# Proxy gap検証計画 (2026-08-24)

## 目的と用語

実行時にはDNNへ探索rootを一度だけ入力し、そこで決めたblendを探索終了まで固定する。探索中の
各局面でDNNを再実行しない。この制約を維持したまま、棋譜上の先局面を使った従来学習と、固定探索器が
実際に訪れるqsearch末端を使った学習の差を検証する。

ここで**棋譜proxy leaf**とは、同一棋譜でrootより1--50手先から一様復元抽出した局面をqsearchし、
そのPV終端へ進めた局面を指す。**実探索leaf**とは、`Threads=1`、固定nodesの通常探索が
`depth <= 0`でqsearchへ入る時点の局面を指す。訪問回数を母集団とするAlgorithm Rのreservoir samplingで
rootごとに抽出し、固定`nn.bin`によるexact qsearchのPV終端を学習recordにする。

実探索leafの**教師score**は、sampleされたqsearch entryで固定`nn.bin`をexact qsearchした戻り値である。
PV終端の手番がentryと異なる場合だけ符号を反転する。候補routerや候補expertの出力は教師生成に使わない。

この文書で**改善root割合**とは、同じrootと同じleaf groupについて、候補checkpointのgroup平均lossが
初期checkpoint 510より小さいrootの割合を指す。**A/B再現**とは、同じroot集合から独立にsampleした
8 leafずつのAとBで、root別loss差の平均と符号が再現することを指す。指し手一致率ではない。

## データ分離と条件

- train root: `tmp/root_grouped_router_large_v1/train`と同じ元棋譜系列から500,000 root
- validation root: trainとは別系列の`val16_clean`から20,000 root
- 通常探索: 現行YaneuraOu、`Threads=1`、`nodes=1000`、`USI_Hash=16`、定跡off
- 各train root: 8 leaf、各validation root: 16 leafをA/B各8に分割
- 探索評価と教師label: `bin/eval/nn.bin`
- router学習: checkpoint 510から開始し、experts固定、adapterのみ、従来root-grouped task lossと同条件
- checkpoint選抜: validation Bのみ。Aは選抜後の1候補に一度だけ使う

PackedSfenは棋譜手数を保持しないため、探索へ渡すSFEN末尾はPackedSfenValueの`gamePly`から復元する。
16 leafを得られないrootは除外し、棋譜proxy比較側も残ったroot recordに正確に揃える。

## 判定

主評価は実探索leaf上のroot paired比較である。

1. 既存の棋譜proxy 500万root候補が実探索validationへ転移するかを測る。
2. 実探索leafで学習した候補をvalidation Bで選び、Aで確認する。
3. 同じroot数の棋譜proxy学習候補とも比較し、データ量だけの差を分離する。

既存proxy候補が実探索leafで悪化し、実探索leaf学習候補がA/Bとも改善する場合、実用上無視できない
proxy gapがあると判断する。bootstrapはrootを再標本化し、95%区間を報告する。なお従来proxy recordと
実探索recordでは教師scoreの作り方も異なるため、最初の判定は「leaf分布だけ」でなく、現在のproxy生成法
全体の転移gapである。必要なら次段で棋譜proxy endpointを固定`nn.bin`で再labelし、局面分布だけを分離する。

## 24時間内の打ち切り規則

500,000 rootを1巡ごとにcheckpoint化する。validation Bが悪化したらNewBobで学習率を0.5倍にし、
3回連続で`2e-5`以上改善しなければ同一データでの追加学習を止める。そこで飽和した場合は、
棋譜proxyの固定`nn.bin`再labelによる分布単独比較へ移る。
