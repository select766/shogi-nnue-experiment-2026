# 研究記録レビューと既存対局の再解析 (2026-09-20)

## 判断

現時点で次に進める価値が最も高いのはdecision-aligned目的である。既存14,000局の
開始局面ペア単位再解析でも`+6.677 Elo`、名目95%区間`[+1.356,+11.997]`となった。
一方、これはtask-only fine-tune対照に対する、旧対局手順・単一学習seed・固定10万nodesでの
小効果である。標準HalfKPを上回ること、同じ実時間で強いこと、学習seedをまたぐ再現は未検証。
`H-DECISION-ALIGNED-LOSS`の支持はこの条件へ限定し、独立再現を新仮説として残す。

モデル変更より先に、履歴とキャッシュを含む対局手順を整える。今回の作業は記録レビュー、
保存結果のCPU再集計、外部エンジンを起動しない呼出し検査である。新しい学習・対局は行っていない。
旧JSON、エンジン、学習実装は変更していない。追加検証コードは1時間以内で終了した。

## 1. 対応のある対局として再集計

従来の`run_match.elo_diff`は1局ごとの勝敗分布から標準誤差を計算する。開始局面を
先後反転して2局ずつ使う設計では、各局面の2局平均scoreを1観測として扱う。
本解析はその不偏標本分散から平均の標準誤差を求め、
`Elo = 400 log10(p/(1-p))`の微分で変換した正規近似区間である。
局面ごとの依存を考慮しても、区間が必ず広がるわけではない。

| 標本 | 開始局面数 | Elo | ペア単位95%区間 |
|---|---:|---:|---:|
| 当初4,000局 | 2,000 | +7.297 | [-2.695,+17.290] |
| 追加8,000局のみ | 4,000 | +6.689 | [-0.401,+13.778] |
| 合計12,000局 | 6,000 | +6.892 | [+1.110,+12.673] |
| 感度追試2,000局のみ | 1,000 | +5.386 | [-8.167,+18.938] |
| 合計14,000局 | 7,000 | +6.677 | [+1.356,+11.997] |
| 当初標本を除く追加10,000局 | 5,000 | +6.428 | [+0.143,+12.714] |

14,000局のペア合計score `0,0.5,1,1.5,2`の度数は`1382,194,3704,213,1507`。
勝敗数、完全な先後ペア、局面重複、4,000→12,000→14,000局の包含関係を保存明細から検査した。
同じプロセスで対局した100局chunkを単位にした感度解析でも区間は`[+1.425,+11.928]`だった。

ただし、これらはモデル選択・実験系列の多重性・停止判断を補正していない名目区間である。
12,000局への拡張計画は当初4,000局の正方向結果を見た後に選ばれた。追加8,000局に先立って
計画を固定した点は適切だが、研究全体が最初から12,000局の単一検定だったわけではない。
追加10,000局の集約も今回の事後的感度解析であり、新しい確証試験とは呼ばない。

## 2. データ分離の限界

SFENの手数を除いた「盤面・手番・持駒」で、2,000 rootのutility教師と評価局面を照合した。

| 照合 | 重複する局面数 |
|---|---:|
| 教師train 1,600 / validation 400 | 1 |
| 教師全体 / accuracy validation 10,000 | 2 |
| 教師全体 / accuracy test 10,000 | 1 |
| 教師全体 / 対局開始局面7,000 | 1 |

教師2,000行は1,999固有局面だった。対局の重複1局面・2局を除いた13,998局でも
`+6.678 Elo`、区間`[+1.357,+11.998]`で、今回見つけた直接重複は結論を説明しない。
一方、「別splitだから学習と独立」とは断定できない。全pretrainingデータとの重複や
同一元棋譜の近接局面までは検査していない。既存HCPE評価JSONLに元棋譜IDはなく、
SFEN重複なしは元棋譜単位の独立性を保証しない。今後は出典と元棋譜IDを保持して分割する。

## 3. 対局手順にある未切り分け要因

### 着手履歴

`src/train_nnue/run_match.py::play_game`は毎手`position sfen <現在局面>`を送る。
実関数にspy engineを渡す6手の検査でも、6回すべて着手履歴なしだった。
runner側のboardは履歴を保持して千日手を判定するが、エンジンの探索は開始局面からの
着手列を受け取れない。エンジンと対局管理側の履歴情報が一致していない。
棋力差への影響方向・大きさは今回測っていない。

### 動的重みと探索キャッシュ

decision-aligned対局の両側は`clear_hash_each_move=false`で、エンジンoptionsにも
`ClearTTOnDynamicWeights`の指定がない。現サブモジュールの同optionは既定値falseであり、
`on_dynamic_weights_updated()`はこの場合TTと探索統計を消去しない。
accumulatorと評価hashの無効化は別途行っているので、「全キャッシュが古い」わけではない。
runnerは対局境界でも`isready/usinewgame`を呼ばず、chunk内でエンジンを使い回す。
旧結果には実行時バイナリのhashや全optionのdumpがないため、当時の内部状態を完全には復元できない。

root統計の4,000局では明示的に毎手hash clearを行っており、研究間で手順も異なる。
旧decision-alignedの差を「新しい評価関数だけの効果」とする前に、履歴とキャッシュ条件を
揃えた追試が必要。両モデルに同じ手順を適用していても、モデルごとの交互作用は相殺されると限らない。

## 4. 仮説の読み替え

- `H-DECISION-ALIGNED-LOSS`: 旧条件での支持を維持。上記の名目区間、対照、手順の限定を追記。
- `H-TAIL-OBJECTIVE`: tail/mean loss改善の支持は維持。loss上位leafが探索の意思決定上も重要だと
  実証したわけではなく、bestmove差`+0.21pt, p=0.6325`から棋力を支持しない。
- `H-ROOT-FEATURES`、`H-ROOT-REPRESENTATION`、`H-TASK-ALIGNED-EXPERTS`、
  `H-EXPERT-DIVERSITY`: 過去の棄却は検証した介入・screening規則の範囲に限定する。
  7特徴・幅256/512・32手幅専門化・偏差2倍の不採用を、特徴/表現/多様性一般の否定に広げない。
- `H-LEAF-LOSS-STRENGTH`: 4,000局の区間は正負両方を含むため、同等性や効果なしの証明ではない。
  棋力改善の選抜指標としてleaf loss単独を使わない判断は維持する。
- 候補手の種類数を増やすことは、有用な候補を得るための診断であり最終目的ではない。
  64--384 rootで3指標すべての改善を要求したscreeningの不通過を、大きな一般仮説の棄却へ
  読み替えない。特にphase専門化の多様度差`-0.0625`だけから棋力悪化は言えない。
- utility教師は候補10k/reference100k nodesで作られた。一方horizon追試では候補順位の
  10k→1m相関が低い。decision-alignedの良好な差が、この旧教師の最適性を保証するわけではない。
- hard方向教師は「logit +1で良かったexpert軸」を直接8次元gateの分類先にする。
  実際に探索したblendと教師gateは同一でなく、変更が成功した理由にはroot依存routingだけでなく
  全体的なexpert利用率の変化も残る。固定gate対照で因果を切り分ける価値がある。
